# Модуль агента Person 1

Область работы: `src/agent.py`, `src/schemas.py`. Парсинг Word/PDF/Excel,
интерфейс и экспорт заключения реализуют другие участники. README проекта
не изменён. Документы организатора используются как данные, а не инструкции.

## Установка и вызов

Python 3.10+; из корня проекта:

```powershell
python -m pip install -r requirements-agent.txt
$env:NVIDIA_API_KEY = "<ваш ключ>"
$env:NIM_MODEL = "<идентификатор модели NIM с поддержкой function calling>"
# Необязательно: адрес собственного NIM вместо NVIDIA hosted API
# $env:NIM_BASE_URL = "http://localhost:8000/v1"
```

Ключ берётся из `NVIDIA_API_KEY` или `NIM_API_KEY`. `.env` автоматически не
читается: загрузка конфигурации принадлежит приложению. Ключ нельзя коммитить.
Идентификатор модели задаётся явно: поддержка инструментов зависит от модели
и развёртывания. Hosted endpoint по умолчанию — `https://integrate.api.nvidia.com/v1`.
Вызов передаёт полный входной комплект указанному NIM endpoint.

```python
from src.agent import analyze_documents

before = [{
    "id": "audit-v8", "name": "Положение, редакция 8",
    "clauses": [{"id": "3.4", "text": "БВА состоит из ДНМ и ДККМ."}],
}]
after = [{
    "id": "audit-v9", "name": "Положение, редакция 9",
    "clauses": [{"id": "3.4", "text": "БВА состоит из ДИТААД, ДОА, ДНМ и ДККМ."}],
}]
result = analyze_documents(before, after)
json_for_ui = result.model_dump(mode="json")
```

Пример сокращён и не заменяет полный комплект. Парсер сохраняет все значимые
пункты, подпункты и таблицы в `clauses`, в исходном порядке. `Document.id`
уникален внутри before/after, `Clause.id` — внутри документа. Для фрагмента без
номера парсер присваивает стабильный идентификатор (например, `table-2-row-3`),
который UI умеет находить. Не генерируйте вымышленные номера страниц.

Результат содержит `unit_changes`, `function_mappings`, `findings`, `summary`,
`limitations`, `requires_human_review`. Все поля обязательны; отсутствие
элементов обозначается пустым списком. Ссылка включает `side`, `document_id`,
`clause_id`, `quote`. Имя документа UI получает из входа по стороне и id.
Перечни допустимых статусов и JSON Schema доступны в `src.schemas` и через
`AnalysisResult.model_json_schema()`.

## Протокол и ограничения

Агент передаёт схему как инструмент `submit_analysis` и явно выбирает его через
`tool_choice`. Инструмент возвращает данные; произвольные функции не исполняются.
Это соответствует [протоколу NIM function calling](https://docs.nvidia.com/nim/large-language-models/1.13.0/function-calling.html).
Неподдерживаемый `strict` провайдеру не передаётся: JSON, Pydantic-схема,
согласованность сторон, наличие пунктов и точность цитат проверяются локально.
Текстовый ответ без tool call отклоняется. Усечённый ответ не считается успешным.
Некорректный результат перезапрашивается до трёх попыток, затем выбрасывается
`StructuredOutputError`. Сетевые ошибки представлены как `NIMRequestError`;
SDK отдельно повторяет временные ошибки до двух раз. Тела ошибок не выводятся.

Синхронный вызов может занимать несколько минут. В async API запускайте его
в рабочем потоке, не блокируя event loop. `NIMAgent` можно переиспользовать как
контекстный менеджер; внедрённым `client` управляет вызывающий код.

По умолчанию максимум 220 000 символов сериализованного входа и 12 000 токенов
выхода. Это предохранитель, не оценка токенов: подберите лимиты под контекст
конкретной модели, включая промпт, схему и ответ. Большой комплект отклоняется
до отправки, без скрытой обрезки. Автоматического chunking/retrieval нет: для
него нужно согласовать с командой глобальное сопоставление функций между частями.

Проверка цитат подтверждает существование фрагмента, но не смысловую
обоснованность вывода, полноту поиска или отсутствие prompt injection. Итог
всегда требует проверки сотрудником; проверка законодательства и бенчмаркинг
без дополнительных исходных документов не выполняются.

## Проверка

```powershell
python -m unittest discover -s tests -p test_agent.py -v
```

Тесты без сети проверяют контракт NIM, восстановление после неверного JSON,
ошибки схемы, неизвестные источники, вымышленные цитаты, перенумерацию пунктов,
ограничение повторов, усечение ответа, входные лимиты и ошибки провайдера.
Это тесты протокола и валидации, а не доказательство качества реальной модели.

Для ручной проверки на приложенных редакциях 8 и 9: в пункте 3.4 редакции 8
перечислены ДНМ и ДККМ; в редакции 9 к ним добавлены ДИТААД и ДОА. Пункты
подчинения далее перенумерованы. Агент должен сохранить ДНМ/ДККМ при сравнении,
не объявлять потерю функций из-за сдвига нумерации и не назначать обязанности
новым департаментам лишь по их названиям. Эти ожидания — контрольные наблюдения,
а не зашитый в промпт ответ. Полные документы в репозиторий не копируются.

Живой прогон NIM требует ключа и выбранной модели; без него семантическое качество
на полном комплекте и совместимость конкретного endpoint остаются непроверенными.
